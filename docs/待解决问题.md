## P0 待解决

### Agent：真实模型动态规划验收

当前状态：代码已经具备 LLM Planner、结构化动作、问题导向工具选择、问题导向公开检索、Replan 和停止条件；未配置 LLM 时会显式使用 `DETERMINISTIC_FALLBACK`。本轮没有启动真实后端任务，因此不能把规则降级测试等同于真实模型规划质量。

建议方案：用同一标的分别运行“最近两个季度毛利率变化原因”和“近期价格波动风险”，保存 `/api/research-runs/{taskId}/trace`，确认计划、工具序列和查询参数不同；再人为制造 `EVIDENCE_INSUFFICIENT`，确认下一轮采集工具发生变化而不是只重写。

### Agent：恢复与工具幂等边界

当前状态：AgentState、turn、tool call、参数 SHA-256、任务租约和恢复调度已实现，但真实数据库上的中断窗口没有验证。当前检查点在轮次结束保存，仍需证明工具成功落库后进程中断不会重复访问外部数据源。

建议方案：增加故障注入点并在 MySQL Testcontainers 中终止第一次执行；恢复时先查询成功的 `agent_tool_call` 并重建已执行摘要，再继续后续动作。该项完成前不能宣称已经覆盖 exactly-once，只能描述为可恢复、幂等设计。

## P1 待解决

### 数据源：TuShare 联调与硬化

当前状态：已新增 10 个评测样例股票的本地主档，并新增 `TushareMarketDataProvider`，可通过 `TUSHARE_API_KEY` 采集 TuShare 财务和日行情基础指标。连接/读取 timeout 已真正应用到 HTTP 客户端，Provider 聚合也有统一超时、取消与 `DATA_MISSING` 降级；缓存、限速和真实错误分类仍未完成。

建议方案：用真实 TuShare token 继续复核贵州茅台营收同比 6.54% 与 ROE 10.57%；随后补 provider 级缓存、限速、接口权限错误提示和更多行情序列指标。

### 网页证据：Tavily Extract 联调与质量基线

当前状态：已写入 `TavilyExtractClient`、候选 URL 优先级、批量正文提取、合格摘要降级和公开网页质量门控；配置为最多 3 个 URL、单次 10 秒、网络错误或 5xx 最多重试 1 次。相关单元测试已随 2026-07-15 后端 128 项全量回归通过，但尚未运行真实 Tavily 调用，不能确认不同财经站点的提取成功率、额外 P95 延迟和 credits 消耗。

建议方案：使用 `600519` 混合检索记录 Search/Extract 的成功 URL、失败 URL、耗时和最终有效新闻数量；至少覆盖交易所公告、普通财经正文、登录页和行情导航页，再决定是否增加域名白名单或 advanced extraction。

### 评测：真实 Golden Set 与模型基线

当前状态：离线评测 v1 已实现 20 个冻结报告样例、24 个检索标注、稳定 `chunkId`、Recall/Precision/MRR/NDCG、JSON/Markdown 产物、显式基线更新和 PR 强门禁；Judge 与真实股票/ETF 冒烟有独立手动/定时工作流，缺 Key 时明确 `SKIPPED`。当前冻结样例主要用于机制回归，尚不能代表真实线上准确率；Judge、P95 延迟和 Token 也还没有积累可审查的非零历史基线。

建议方案：从已确认的 Bad Case 中脱敏沉淀跨行业、跨报告期 Golden Set；连续运行 Judge/真实数据工作流后再提交模型质量、P95 和 Token 基线，并在数据量足够时评估趋势存储与管理页面。

### LLM：Planner 与 Writer 端到端回归及延迟基线

当前状态：历史 Writer 使用 `qwen3.7-max` 的压缩请求曾取得 50.859 秒结果；本轮新增 Planner 后尚未重新测量计划、动作和 Writer 的总 Token、P50/P95、降级率与结构非法率。

建议方案：重启后端后用 `600519` 混合检索连续生成报告，确认 `generation-mode: llm`、正文关键指标带对应 `[E#]`、一季度 ROE 标注未年化、低质量网页不进入正文，同时比较新旧 Writer 的 P50/P95；若降级，数据库应记录 `DEGRADED` 和稳定原因分类。

### 前端：独立股票报告页

当前状态：2026-07-17 已新增 `/reports/:reportId` 独立研究页，支持版本时间带、逐行对比、证据详情与来源筛选、`[E#]` 锚点、ETF 行情图和多空论据展示；报告库已有独立入口，生产构建通过。

建议方案：下一步只补段落/证据旁 Bad Case、风险维度筛选和长时间线筛选，并为逐行差异增加章节摘要。

### 资产类型：ETF 深度数据

当前状态：已新增 `StockAssetType.ETF`，支持沪市 `5xxxxx` 和深市 `15xxxx/16xxxx/18xxxx` ETF 解析；ETF 不套普通股票财务指标。TuShare 已聚合 `fund_daily`、`fund_basic`、`fund_nav`，保存 60 日行情、基金资料、业绩基准、单位/累计净值、资产净值和同日折溢价。持仓、跟踪误差和申赎清单还未接入，`total_netasset` 的展示单位也需真实 token 复核。

建议方案：后续接入持仓、跟踪指数收益、跟踪误差和申赎清单；按 token 权限增加 provider 级开关、缓存、限速和接口权限错误提示。

### 可视化：ECharts 行情图表

当前状态：ETF 已落地 60 日行情序列和按路由懒加载的 ECharts 组件，展示 K 线、收盘线、成交额和单位净值基准；无数据时有明确空状态。普通股票仍只有 `daily_basic` 估值/市值证据。

建议方案：后续为普通股票接入 TuShare `daily`/`weekly`，并增加均线、RSI 与区间切换；继续保持 Java/前端实现，不引入 Python 图表链路。

### Agent 门禁：证据冲突与审查回流

当前状态：确定性 `BullBearCaseBuilder` 已作为白名单工具输出证据约束的正反条件；引用审查出现证据不足时 Runtime 可 Replan。当前仍缺更细的 `EVIDENCE_CONFLICT`、`NUMERIC_MISMATCH`、`CITATION_MISSING` 分类和按原因选择不同动作的集成测试。

建议方案：补风险裁判和证据冲突仲裁，扩充真实多空 Bad Case；若后续让 LLM 优化表达，仍必须保留 Java 数字边界、证据编号校验和现有 fail-closed 门禁。

### 执行资源：并发受控与观测

当前状态：Agent 任务和工具调用已使用固定线程数 + 有界队列，并暴露 active/queued/rejected 指标；整体运行、单工具和 TuShare HTTP 均有超时。Agent turn、tool call、Checkpoint、租约心跳和停止原因可追踪；当前仍缺主动取消、跨实例并发控制，以及外部工具完成与检查点之间的原子/幂等恢复验证。

建议方案：后续增加任务主动取消；多实例部署时使用数据库唯一占位或 Redis 分布式 single-flight。若要让纯公开数据报告跨用户复用，必须先增加快照公开性分级、私有证据零混入校验、报告归属复制和跨租户安全回归，不能直接移除 `ownerId` 条件。
