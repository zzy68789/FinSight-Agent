## P0 待解决

### Agent：真实模型动态规划验收

当前状态：代码已经具备 LLM Planner、结构化动作、问题导向工具选择、问题导向公开检索、Replan 和停止条件；Replan 会直接读取最近观察、门禁问题、补证据尝试与证据增量，补证据次数和通用进展指纹也已纳入服务端停止策略。未配置 LLM 时会显式使用 `DETERMINISTIC_FALLBACK`，本轮没有启动真实后端任务，因此不能把单元测试等同于真实模型规划质量。

建议方案：用同一标的分别运行“最近两个季度毛利率变化原因”和“近期价格波动风险”，保存 `/api/research-runs/{taskId}/trace`，确认计划、工具序列和查询参数不同；再人为制造 `EVIDENCE_INSUFFICIENT`，确认下一轮采集工具发生变化而不是只重写。

### Agent：恢复与工具幂等边界

当前状态：`DurableTurnCommitModule` 已把 Planner 动作、工具结果、证据、快照、指标、turn、轻量 Checkpoint、事件 outbox 和租约心跳收敛为同一事务；最终 PASS 把报告、快照冻结、任务完成和完成事件原子提交。`openTurn` 锁定当前租约行，工具开始、commit/finish 的 SQL 都按 `lease_owner + lease_epoch` fencing，`NEXT_ACTION` 遥测与 turn 唯一关联；未提交 `PLANNED` turn 会复用原始动作而不重新调用 Planner，`AgentStateStore` 会从已提交 journal 重建调用哈希。单元测试已覆盖过期 lease 的前置写与提交拒绝，但真实 MySQL 上各写点回滚和 V1→V9 迁移仍未验证。

建议方案：在 MySQL Testcontainers 中为工具结果、证据、指标、报告、快照冻结、checkpoint 和 outbox 写点注入异常并验证回滚，同时验证重复提交、指标 delete+insert、旧 `lease_epoch` open/start/commit/finish、journal 重放和 outbox 重发。外部 Provider 已完成、事务提交前宕机仍可能再次访问外部系统，应通过 Provider 幂等键或结果暂存进一步缩小窗口；完成前只能描述为 at-least-once 外部调用 + 原子数据库提交。

## P1 待解决

### 数据源：TuShare 联调与硬化

当前状态：已新增 10 个评测样例股票的本地主档，并新增 `TushareMarketDataProvider`，可通过 `TUSHARE_API_KEY` 采集 TuShare 财务和日行情基础指标。证券搜索/预览 API 已对名称确认状态建模，但名称搜索仍只能覆盖这 10 个本地主档股票；ETF 和其余 A 股只能按代码解析，不能假装已经确认名称。连接/读取 timeout 已真正应用到 HTTP 客户端，Provider 聚合也有统一超时、取消与 `DATA_MISSING` 降级；缓存、限速、全市场主档同步和真实错误分类仍未完成。

建议方案：用真实 TuShare token 继续复核贵州茅台营收同比 6.54% 与 ROE 10.57%；随后新增低频证券主档同步与本地持久化/缓存，覆盖股票和 ETF 的代码、名称、交易所、资产类型及状态，搜索请求只读本地主档，不在用户每次输入时直连 TuShare；同时补 provider 级缓存、限速、接口权限错误提示和更多行情序列指标。

### 网页证据：Tavily Extract 联调与质量基线

当前状态：已写入 `TavilyExtractClient`、候选 URL 优先级、批量正文提取、合格摘要降级和公开网页质量门控；配置为最多 3 个 URL、单次 10 秒、网络错误或 5xx 最多重试 1 次。相关单元测试已随 2026-07-15 后端 128 项全量回归通过，但尚未运行真实 Tavily 调用，不能确认不同财经站点的提取成功率、额外 P95 延迟和 credits 消耗。

建议方案：使用 `600519` 混合检索记录 Search/Extract 的成功 URL、失败 URL、耗时和最终有效新闻数量；至少覆盖交易所公告、普通财经正文、登录页和行情导航页，再决定是否增加域名白名单或 advanced extraction。

### 评测：真实 Golden Set 与模型基线

当前状态：离线评测 v1 已实现 20 个冻结报告样例、24 个检索标注、稳定 `chunkId`、Recall/Precision/MRR/NDCG、JSON/Markdown 产物、显式基线更新和 PR 强门禁；Judge 与真实股票/ETF 冒烟有独立手动/定时工作流，缺 Key 时明确 `SKIPPED`。当前冻结样例主要用于机制回归，尚不能代表真实线上准确率；Judge、P95 延迟和 Token 也还没有积累可审查的非零历史基线。

建议方案：从已确认的 Bad Case 中脱敏沉淀跨行业、跨报告期 Golden Set；连续运行 Judge/真实数据工作流后再提交模型质量、P95 和 Token 基线，并在数据量足够时评估趋势存储与管理页面。

### LLM：Planner 与 Writer 端到端回归及延迟基线

当前状态：历史 Writer 使用 `qwen3.7-max` 的压缩请求曾取得 50.859 秒结果，但这不是新 Agent 的端到端基线。现在 `PlannerModelPolicy` 已让普通动作优先 FAST、建计划/Replan/复杂恢复使用 SMART、结构失败升级 SMART；`agent_planner_call` 和 Trace 已能汇总实际模型、决策类型、路由原因、结构合法率、Token 与 P50/P95。由于本轮没有真实模型流量，数据库尚无可用于决策的非零样本。

建议方案：重启后端后用固定股票/ETF问题集连续生成报告，分别比较 ordinary/recovery/replan 的 FAST/SMART 结构合法率、路由正确率、最终门禁通过率、Token 和 P50/P95；同时确认 `generation-mode: llm`、正文引用和季度口径。只有质量不下降时才扩大 FAST 范围，不能仅凭单次耗时切模型。

### 提交恢复：真实网络与数据库故障验收

当前状态：创建任务和订阅事件已拆成两个请求；数据库以 `(owner_id, client_request_id)` 唯一约束保证同用户幂等，重复 key 会验证完整请求载荷，遗留 `CREATED` 任务可由相同请求补调度。前端在本地保存 pending key 与活动 task/thread/sequence，刷新通过 Task + Trace 恢复，再使用 `Last-Event-ID` 接续；获得回执前的 4xx 会释放 pending，网络不确定错误保留 key 供重试。

建议方案：在 Docker/CI 实跑 Flyway V1→V9 与唯一键/证据归属字段回归，并使用浏览器网络拦截验证 POST 响应丢失、首次 SSE 拒绝、SSE 中途断开、页面刷新和跨账号登录。当前本地活动指针不包含后端 Session 语义，且尚未实现显式“放弃恢复/取消后台任务”操作；这些应分别在真实联调和后续任务取消/多会话阶段完成。

### 可比证券：真实数据口径和端到端归属

当前状态：最多 3 个同类可比证券、后缀规范化、独立快照/证据归属、Planner 采集守卫、股票/ETF 确定性比较指标和 `DATA_MISSING` 已落地；报告正文与引用附录能够区分主证券和可比证券。当前验证来自固定 Provider 与单元测试，尚未运行真实 TuShare 股票/ETF 对比任务，也未在浏览器复核选择器、Trace、证据检查器和报告的完整归属链路。

建议方案：使用真实 token 运行至少一组股票和一组同类 ETF，对照 TuShare 原始字段核验 PE/PB、营收同比、单位净值和折溢价；模拟一个可比证券无数据，确认其独立标记 `DATA_MISSING` 且不阻断其他证券。浏览器验收需要逐项核对请求 `comparison_tickers`、任务快照、数据库 `subject_code/comparison_snapshot_id`、报告 `[可比 代码]` 和证据检查器。

### Agent 事件：投递运维与容量边界

当前状态：`agent_event_outbox` 已用版本化契约和任务内 sequence 统一实时 SSE 与历史 Trace，最终完成事件与业务事务同提交。V7 已增加数据库原子 claim、过期接管、指数退避和死信；SSE 端点支持 `Last-Event-ID`/`afterSequence`，回放与实时订阅间的竞态由缓冲排序消除，活跃订阅通过共享数据库补齐其他实例事件，前端按 `taskId + sequence` 幂等并有限重连。当前死信只保存在数据库，没有告警、管理查询或受控重放；共享数据库补发按活跃 task 固定轮询，也尚无多实例容量数据。

建议方案：增加 outbox 待发布/重试/死信数量、发布延迟和活跃订阅数 Micrometer 指标，为管理员提供只读死信查询与显式重放操作；随后用多实例、慢消费者和数据库短时不可用场景做压力/恢复测试，按结果决定是否加入数据库通知、Redis 通知或自适应轮询。继续保留 outbox 为 canonical source 和消费端 sequence 幂等，不能把传输语义宣传为 exactly-once。

### Agent 门禁：证据冲突与审查回流

当前状态：`QualityGateDecisionEngine`、`EvidenceRecoveryDirective` 与完整补证据重算链路已经实现。2026-08-12 又新增同指标同报告期的结构化仲裁：交易所/法定披露、TuShare、结构化财报、上传报告、普通公开网页、公开研究和本地主档使用固定优先级；容差内来源降为旁证，唯一高优先级来源可解决冲突，同级未决冲突由 `CitationReviewer` 输出 `EVIDENCE_CONFLICT` 并回到补证据。仲裁结果进入快照、证据账本、生成哈希和报告附录，补证据到达后会清除临时结论并重仲裁。当前仍未用真实 Tavily/TuShare 验证来源权重、冲突命中率、差异化 query 的新增事实相关性和额外延迟。
