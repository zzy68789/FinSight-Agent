## P0：受约束 Research Agent Runtime

- 新增 `GET /api/securities/search?query=...` 与 `GET /api/securities/{ticker}/preview`：代码输入返回规范化证券身份，名称输入从本地 `AShareCompanyDirectory` 返回最多 10 个稳定排序候选；名称存在歧义时不自动选择。受支持但主档缺少名称的代码明确返回 `nameResolved=false`，不把“待识别上市公司/ETF”作为已确认名称暴露给前端。
- `ResearchRunRequest` 新增类型化 `ResearchIntent`，支持 `COMPREHENSIVE`、`FINANCIAL_QUALITY`、`VALUATION_RISK`、`ETF_TRACKING`、`EVENT_IMPACT`。`ResearchIntentPolicy` 在任务入队前校验资产类型，财务质量仅适用于普通股票、ETF 跟踪仅适用于 ETF；旧入口固定使用综合研究保持兼容。
- 研究意图进入 `createPlan` prompt、`PlannerContextProjection`、确定性 fallback 证据需求和 provider 选择，但不在 Runtime 中按意图写死工具顺序；Planner 版本升级为 `research-planner-v4-intent-aware-routing`。意图同时进入 `ToolResearchRequest`、请求恢复 SHA-256 和报告复用上下文哈希，避免不同研究目标错误共享 Checkpoint 或历史报告。
- 2026-08-13 后端全量 `mvn.cmd test` 共 213 项测试，零失败、零错误、跳过 3 项；新增覆盖名称/代码搜索、多候选、未知名称、交易所后缀校验、意图与资产类型、Planner prompt/fallback、任务入队校验、请求恢复兼容和意图隔离报告指纹。跳过项仍为真实 Provider、LLM Judge 和 Docker MySQL 集成测试。
- 新增 `POST /api/research-runs`、`POST /api/research-runs/{taskId}/retry` 和 `GET /api/research-runs/{taskId}/trace`；旧 `/api/stock-reports` 只负责把原请求转换为默认研究问题并进入同一 Runtime。
- `ResearchPlanner` 使用 LLM 输出结构化 `ResearchPlan` 和 `AgentAction`；Replan 由 `PlannerContextProjection` 直接把当前计划、最近观察、门禁问题、补证据尝试次数和证据增量送入模型，不再先重新 `createPlan` 再由 Java 追加反馈。模型未配置或结构连续两次非法时明确标记 `DETERMINISTIC_FALLBACK`。
- `PlannerModelPolicy` 对决策分层：创建计划和重规划使用 SMART，普通 `nextAction` 优先 FAST，待补证据、门禁恢复和 FAST 结构失败升级 SMART；`PlannerOutput<T>` 在一次解码后同时返回类型化值与真实模型、Token、耗时、结构尝试等元数据。
- `ResearchAgentRuntime` 执行通用 `plan -> act -> observe -> replan/synthesize/stop` 循环；允许动作只有 `CALL_TOOL`、`CALL_TOOLS_PARALLEL`、`REPLAN`、`SYNTHESIZE` 和 `STOP_INSUFFICIENT_EVIDENCE`。
- `ResearchToolRegistry` 和 `ToolPolicyGuard` 只允许只读白名单工具，禁止交易/下单/仓位/券商能力，校验未知工具、未知参数、重复调用、并行限制和剩余预算；非法动作以 `FAILED_INVALID_ACTION` 停止。
- 第一批工具包含证券解析、公司主档、TuShare 财务、公开行情、用户上传报告、问题导向公开网页检索、确定性指标、风险评估、多空条件和证据覆盖检查。自然语言问题会进入公开检索 query，不再只影响 Writer prompt。
- `EvidenceMemory` 将多次工具结果增量校验、去重并合并为快照；新增证据会使旧指标、风险和多空结果失效，综合前再以最终快照生成稳定摘要。
- `AgentBudgetGuard` 服务端限制默认 8 轮、12 次工具、3 次 Replan、2 次补证据恢复、连续 3 个无进展已提交 turn、单轮 4 个并行工具、2 次报告重写、180 秒整体超时和 30 秒工具超时；客户端只能收紧公开预算。
- `DurableAgentRunner`、`AgentRunRecoveryScheduler` 和 AgentState Checkpoint 保留任务租约、心跳、失败重试和断点恢复；`agent_turn`、`agent_tool_call` 和步骤日志可解释每轮动作、参数摘要、观察、耗时与停止原因。
- `DurableTurnCommitModule` 把 Planner `NEXT_ACTION` 决策、工具结果、证据、快照、指标、turn、`agent-state-v3-lite` checkpoint、事件 outbox 和租约续期集中在一个 `@Transactional` 深模块内；动作遥测通过唯一 `turn_id` 与实际执行轮次绑定。最终 PASS 还会把报告版本、快照冻结、任务结束和 `run_completed` 事件一次提交，避免留下“报告已发布但任务未完成”的中间状态。
- `research_task.lease_epoch` 每次领取任务时单调递增，`openTurn` 会先用 `SELECT ... FOR UPDATE` 锁定当前租约行，工具开始 journal、turn 提交和任务结束的数据库写入也必须同时匹配 `lease_owner + lease_epoch`；即使校验后发生租约切换，旧执行者仍不能写入。
- 若恢复时发现下一个 `PLANNED` turn，Runtime 会反序列化该轮已经持久化的完整 `AgentAction`，同时读取唯一关联的 Planner 元数据作为权威决策，不再次调用模型生成可能同类型但不同工具参数的动作；动作损坏、缺少决策关联或检查点落后于已结束 turn 时一律 fail-closed。
- `ResearchTool` 以 `ToolDefinition` 暴露参数与结果 schema；`ResearchToolRegistry` 把 Planner JSON 解码为 `ToolArguments`。工具只接收由请求和状态复制出的不可变 `ToolContext`，返回 sealed `ToolPayload`，不再直接修改共享 `AgentState`；`ToolStateReducer` 在 Runtime 中集中、串行地应用证券、证据、指标、风险和多空结果。
- 报告综合后仍必须同时通过 `CitationReviewer`、`FinancialComplianceReviewer` 和 `FinancialEvaluator`；`CitationReviewResult` 新增兼容的稳定 `code` 字段，`QualityGateDecisionEngine` 再把三类审查结果归一化为 `EVIDENCE_INSUFFICIENT`、`EVIDENCE_INVALID`、`CITATION_INVALID`、`NUMERIC_MISMATCH`、`COMPLIANCE_VIOLATION` 等稳定类型，并唯一映射到补证据、确定性重算、带反馈重写或 fail-closed 停止。Runtime 不再拼接 Reviewer 文案并用 `contains` 猜测下一步。
- `QualityGateDecision` 会进入 AgentState Checkpoint、`review_completed` SSE 和 `quality_gate_routed` Trace；数字门禁失败时会清空旧指标与风险结果，并只释放 `calculate_financial_metrics`、`assess_financial_risk` 两个确定性工具的重复调用锁，禁止让 LLM 自行修正关键数字。
- `EvidenceRecoveryDirective` 保存补证据轮次、触发问题码、基线证据数、实际工具参数和新增有效证据数。待补证据期间，Planner 和 `ToolPolicyGuard` 只允许新的 `producesEvidence=true` 调用或明确停止；优先切换尚未使用的数据源，来源耗尽后为公开检索生成递增且不重复的 query。
- 补证据恢复有独立 `maxEvidenceRecoveries` 预算，耗尽时以 `EVIDENCE_RECOVERY_EXHAUSTED` 原因 fail-closed；`ProgressFingerprint` 同时哈希计划问题、证据、指标和门禁路由，连续多个已提交 turn 没有语义进展时停止。旧“连续两轮证据工具无新增”的局部停止分支已经退役，服务端只保留这一套可配置的通用进展语义。
- 证据工具产生新增有效证据后，`EvidenceMemory` 会使旧指标、风险、多空结论和覆盖检查失效，并只给相应确定性工具开放一次受控重执行；完整 Runtime 回归已覆盖 `synthesize -> quality gate -> replan -> 新 query -> observe -> 指标/风险重算 -> review PASS`。
- `FinancialEvidenceConflictResolver` 对同一指标、同一报告期的多来源数值执行确定性仲裁：绝对误差不超过 0.01 或相对误差不超过 0.5% 时保留最高优先级来源并把其余来源记为旁证；超出容差时由唯一更高优先级来源胜出，若最高优先级来源彼此冲突则全部标记 `EVIDENCE_CONFLICT`。`CitationReviewer` 输出同名稳定码，现有质量路由会强制回到补证据而不是改写掩盖冲突；新增来源到达后会清除临时仲裁码并重仲裁。
- 已删除 `StockReportWorkflow`、`StockReportRunner`、旧恢复调度、阶段式 Checkpoint、single-flight 协调器及相关测试；`BullBearResearchAgent` 已改名为确定性的 `BullBearCaseBuilder` 并仅通过工具调用。

## Research Launcher

- `ResearchWorkspace.vue` 已把任务输入区拆为 `ResearchLauncherSidebar`、`ResearchReadinessStepper`、`SecuritySubjectPreview`、`ResearchScopeOptions` 和 `ResearchSubmitBar`。启动链路固定为“搜索并确认证券 → 选择研究意图 → 明确自然语言问题 → 检查证据范围 → 创建 Agent Run”，正式请求只提交候选返回的规范化 `fullCode`，名称文本不再直接充当 `ticker`。
- 证券搜索使用 400ms 防抖和单调请求令牌；输入变化会立即使旧候选失效，迟到响应不能覆盖最后一次输入。完整证券代码命中唯一候选时自动确认，名称搜索即使只有一个候选也保留用户确认步骤。
- `resolveResearchReadiness` 统一表达等待标的、解析中、等待候选确认、等待问题、等待文档、已就绪和提交中七种状态；按钮禁用原因与状态提示使用同一结果，提交开始后禁止重复创建 Run。
- 研究意图按资产类型过滤：普通股票只显示财务质量，ETF 只显示 ETF 跟踪；每种意图提供三条中性建议问题，不包含买卖、仓位或收益承诺。截止日、时间范围、研究深度、检索模式和 PDF 证据已收进默认折叠的高级范围，PDF 解析完成前不能提交仅文档任务。
- PDF 选择后只在启动前解析一次，不再在点击启动时重复上传；无上传文档时仍会清理上一轮知识库上下文。前端错误解析会优先展示后端结构化 `message/detail`，不再把可解释的 4xx 统一压缩为状态码。

## Research Mission Control

- 新增 `ResearchMissionControl.vue`，只读取 `useAgentRunProjection` 暴露的 canonical Agent 事件投影；固定 `StatusFlow.vue` 已删除。顶部阶段轨按实际 `run_created / plan_created / tool_* / replanned / synthesis_* / review_* / run_completed|stopped` 标记当前和已完成状态，不展示无法准确计算的百分比。
- `agentEventProjection` 新增请求摘要、最近工具、Replan/补证据次数、质量门禁决策、停止原因和最终轮次/工具统计；`deriveMissionControlView` 再把投影转换为纯展示模型。任务提交时冻结证券、研究意图、问题、截止日和深度，用户修改下一次表单不会污染当前运行摘要。
- Mission Control 使用运行概览、活动轨迹、质量与证据、任务与报告、诊断日志五个视图：计划目标、最近工具、有效证据、门禁/停止原因位于概览；指标、Provider/工具状态、合规问题和 Bad Case 位于质量视图；日志只作为诊断信息，不再长期占据启动器左栏。
- 当前任务列表只查询真实 `CREATED/RUNNING` 状态，最近报告直接使用既有报告记录；没有后端权威数据时不显示队列位置或预计等待时间。任务和报告搜索 SQL 已支持主键、研究问题、thread、任务请求快照中的证券，以及报告正文/标题内容。

## 证券代码研究报告 MVP

- 新增 `POST /api/stock-reports` SSE 入口，支持 `ticker`、`thread_id`、`report_period`、`search_mode`。
- 证券代码解析支持普通 A 股 `6xxxxx -> .SH`、`0xxxxx / 2xxxxx / 3xxxxx -> .SZ`，以及常见 ETF `5xxxxx -> .SH`、`15xxxx / 16xxxx / 18xxxx -> .SZ`。
- 不支持的代码会通过 SSE `error` 事件返回明确业务原因，不再在前端泛化为“网络异常”；当前仍不支持 B 股、债券或北交所标的。
- 新增金融数据模型：`StockSubject`、`FinancialEvidenceItem`、`FinancialEvidenceArbitration`、`FinancialSnapshot`、`FinancialMetricResult`；快照 JSON 兼容旧记录缺少仲裁字段的情况。
- 新增 `FinancialDataProvider` 扩展点，已实现 `UploadedReportProvider`、`PublicMarketDataProvider` 和 `TushareMarketDataProvider`。
- 新增 `AShareCompanyDirectory` 和 `AShareMasterDataProvider`，为 10 个默认评测样例股票补齐公司名称、行业和 `LOCAL_CONTEXT` 证据。
- LLM 只有 API Key 使用用户指定的 `API_KEY`，地址、模型、超时和重试参数直接维护在 `application.yml`；不读取全局 `OPENAI_API_KEY`，避免影响 `cc-switch` 等全局配置。
- 新增 TuShare Pro 授权数据源配置，只有 token 使用 `TUSHARE_API_KEY`，启用开关、地址和超时直接维护在 `application.yml`；未配置 token 时不调用外部接口。
- `TushareMarketDataProvider` 已能把普通股票的 TuShare `income`、`balancesheet`、`cashflow`、`daily_basic` 响应映射为营业收入、营业成本、归母净利润、资产负债、经营现金流、市盈率、市净率和总市值证据；财报行按报告期、标准合并报表、`update_flag` 和公告日期选择唯一版本，上年同期严格按本期日期减一年匹配。ETF 标的聚合 `fund_daily`、`fund_basic`、`fund_nav`，冻结最近 60 个交易日 OHLC/成交量/成交额序列、基金简称、管理人、托管人、业绩比较基准、单位/累计净值、资产净值和同日折溢价率；单个深度接口失败时保留其他结果并写入 `DATA_MISSING`。
- `FinancialEvidenceValidator` 在快照进入指标引擎前标记重复报告期、上年同期错配、未来日期、资产负债异常和低质量网页正文；公开新闻按 URL 去重，并识别登录页、导航页、行情 SEO 占位内容和链接密度异常。`FinancialEvidenceSourcePriorityPolicy` 固定采用交易所/法定披露原文 110、TuShare 授权结构化数据 100、结构化财报 90、上传报告 80、普通公开网页 60、公开研究检索 50、本地主档 30 的来源层级；仲裁候选、胜出值、原因和策略版本随快照持久化。
- `FinancialSnapshotBuilder` 已支持 provider fan-out 并行采集，并为每个数据源记录状态、耗时、证据数量和失败信息；所有 Provider 共用 `finsight.async.financial-provider-timeout` 超时窗口，慢源会被取消并写入 `TIMEOUT/DATA_MISSING`，已完成的数据源结果继续保留。
- 股票报告任务和金融 provider fan-out 使用 Spring 管理的固定线程数 + `ArrayBlockingQueue` 有界执行器，线程数和队列容量均可配置；队列满时明确拒绝并记录 `finsight.async.rejected`，同时暴露 active/queued 指标。TuShare 配置的 timeout 已实际应用到连接和读取超时。
- 公开数据失败时不会阻断流程，会写入 `DATA_MISSING` 证据。
- 新增 `FinancialMetricEngine`，普通股票用 Java `BigDecimal` 计算营收同比、毛利率、净利率、ROE、资产负债率、经营现金流 / 净利润；ROE 新口径使用年初与期末归母权益的平均值，上传报告直接披露的平均净资产仅作为兼容路径；ETF 不套用公司财务指标，输出收盘价、涨跌幅、成交额、单位净值和同日折溢价率。即使调用方传入尚未仲裁的证据，指标索引也会按固定来源优先级选择，不再受 Provider 并行返回顺序影响。
- 新增 `MetricDefinitionCatalog`，集中声明指标公式、`formulaVersion` 和输入依赖；`stock_metric_result.formula_version` 保存实际使用的公式版本。
- 缺少分子或分母时返回 `MISSING_INPUT`，报告中显示“数据缺失”。
- `FinancialRiskScorer` 按基本面 30%、技术面 25%、情绪面 20%、消息面 15%、市场环境 10% 输出五维风险评分；一季度、半年度和前三季度 ROE 明确按未年化阶段性指标处理，不再套用全年 ROE 阈值。
- `FinancialComplianceReviewer` 检查免责声明、保证收益、内幕信息、直接荐股/仓位指令、无审慎边界的股价方向表达和引用审查失败，并输出结构化 `issues` 与合规分数。

## Agent 可靠性与报告复现

- Agent 任务使用固定线程数和有界队列；SSE 断开只关闭推送通道，不改变后台任务最终状态。
- `research_task` 记录 Runtime 类型、轮次、工具调用数、Planner/toolset/policy 版本、停止原因、请求、尝试次数、心跳和数据库租约；恢复调度每分钟领取过期 Agent 任务，最多执行 3 次。
- AgentState Checkpoint 使用请求上下文 SHA-256 隔离不同问题、截止日期、区间、深度和策略版本；`agent-state-v3-lite` 不再内嵌完整证据、快照、报告和审查对象，只保留 ID、哈希、预算/停滞计数、恢复指令和最近短观察，并兼容迁移 v1/v2。`AgentStateStore` 恢复时从快照/指标表加载重对象，并从已提交工具 journal 重建调用摘要；损坏、上下文不匹配或未知版本均 fail-closed。
- 引用、合规和评测失败会先形成可序列化的统一门禁决策；非法 Reviewer 状态或无法解释的引用失败直接路由到 `STOP_FAILED`，不会因自由文本变化绕过最终门禁。Writer 重写时接收统一问题摘要，而不只接收引用 Reviewer 的单一反馈。
- 补证据指令和派生工具重执行权限随轻量 Checkpoint 保存；工具参数历史、成功调用哈希和完成工具集合从 `agent_tool_call` journal 重建，恢复后仍能避开已经提交过的相同 query。
- `FinancialReportFingerprinter` 对最终证据视图生成 `data_snapshot_hash`；`generation_context_hash` 额外包含研究问题、研究意图、截止日期、区间、深度和 Planner/toolset/policy 版本。
- 同一用户下只有上下文完全一致、历史评审为 PASS 且重新通过当前三重门禁的报告才允许复用；不跨用户共享私有证据或报告。
